# בקרת והכנת דוחות חופש גדול — סטטוס פיתוח

אפליקציית full-stack לניהול, בקרה והכנת דוחות ביצוע (לפי `README_מערכת_חופש_גדול.md`).

## איך מריצים

לחיצה כפולה על **`הפעלה.bat`** — מפעיל את השרת ואת הממשק ופותח את הדפדפן.
(פעם ראשונה בלבד: צריך `npm install` בתיקיות `backend` ו-`frontend`. כבר בוצע.)

- ממשק: http://localhost:5273
- שרת (API): http://localhost:3101

לעצירה — סוגרים את שני חלונות ה-cmd.

## Stack

- **Backend:** Node.js + Express + sql.js (SQLite טהור-JS, כמו budget-app). פורט 3101. מסד הנתונים: `backend/chofesh.db`.
- **Frontend:** React + Vite + TypeScript. פורט 5273.

## מבנה מסד הנתונים (README §13)

היררכיה: **לקוח → (רשות) → דוח → מוסד → סל → תנועה**, ומיפויים נלמדים לכל לקוח.

| טבלה | תיאור |
|---|---|
| `clients` | לקוח (שם, חיוב מע"מ §7, אשכול למ"ס §9) |
| `authorities` | רשות (רמה אופציונלית) |
| `reports` | דוח = מסגרת × תוכנית (יחידת המעקב §13); סטטוס + דגלי קליטה |
| `institutions` | מוסד (סמל) — משק כספים סגור §1 |
| `baskets` | סל (תקציב מול ניצול) |
| `transactions` | תנועה — שובל ביקורת §10 |
| `client_mappings` | מיפויים נלמדים לכל לקוח (חתימות שכר, כינויי כרטסת, שיוכים) |

- ✅ לוגיקת תחום מהמפרט: תוויות דוח, סוג תוכנית ותקרת ברוטו (§6), תקרות שעות לפי תפקיד (§4).
- ✅ ממשק: לוח שליטה (כל הלקוחות) · מסך לקוח (רשויות + דוחות) · מסך דוח (קלטים, "מה חסר", סטטוס).

- ✅ **עידון נוסף (2026-09-01):** כשיש כמה עמודות טקסטואליות ("מחלקה" גסה + "תאור סעיף" מפורט) — המנוע בוחר את **המפורטת ביותר** (הכי הרבה ערכים שונים במדגם 200 שורות). בקובץ נתניה: 74 מחלקות לפי "תאור סעיף" במקום 15 גסות ("צהרונים" בלעה 420 שורות).
- ✅ טבלאות `cost_files` (קובץ ברמת הלקוח) + `cost_rows` (שורות מנורמלות עם `report_id` = תוצאת הניתוב).
- ✅ **ניתוב חוצה-פרויקטים:** מעלים קובץ אחד ברמת הלקוח → המערכת מציעה מחלקה→פרויקט → מסך ניתוב לאישור. הבחירה נלמדת (`client_mappings` type `dept_to_project`) ומוצעת אוטומטית בהעלאה הבאה.
- ✅ **כמה קבצים לאותו דוח:** כל השורות שנותבו לדוח מתאחדות אוטומטית (`GET /api/reports/:id/costs`) עם בקרות תלויות-תוכנית (תקרת ברוטו 120/150).
- ✅ ממשק: פאנל "דוחות עלות שכר" במסך הלקוח + מסך ניתוב (מודל) + סקשן "דוח עלות שכר (מנותב)" במסך הדוח עם מדדים וטבלת בקרות.

⚠️ **אזהרת sql.js:** רק תהליך אחד יכתוב ל-DB בכל רגע. אין להריץ סקריפט ניקוי/כתיבה בזמן שהשרת רץ — הוא ישכתב את הקובץ מהזיכרון. לעצור את השרת קודם.

## מה נבנה — צעד פיתוח 2 (מנוע הסטטוס המלא)

- ✅ `lib/status.js` — גוזר אוטומטית לכל דוח: דלי סטטוס (פתוח/לקראת סיום/תקוע על חוסר/מוכן/הוגש), אחוז השלמה, חריגות פתוחות (מבקרות דוח העלות), ו"מה חסר לעשות".
- ✅ `lib/reportCosts.js` — הוצא מ-`reports.js`, מקור אחד לדוח העלות המאוחד (משמש גם את מנוע הסטטוס).
- ✅ לוח ראשי: דליי סטטוס נגזרים + **התראות ממוינות לפי דחיפות** (לחיצה קופצת לדוח) + "כסף על השולחן" (placeholder עד מנוע התקציב).
- ✅ מסך דוח: תג דלי + בר השלמה + "מה חסר" נגזר מהשרת. מסך לקוח: כל דוח עם דלי/אחוז/חריגות.
- הערה: "כסף על השולחן" ותת-ניצול (`underUtilization`) יחושבו בצעד 4 (תקציב מול ניצול).

## מה נבנה — צעד פיתוח 4 (מנוע התקציב)

- ✅ `lib/budgetFile.js` — פרסר מבוסס-תוויות לגיליון "תקצוב לפי מוסד"/"ריכוז נתונים". מחלץ לכל מוסד: סמל, שם, גודל, זכאים ח.ר/ח.מ, ותקציב כולל מחושב. **אומת מול קובץ אמיתי (מעלה אדומים): 6/6 מוסדות תואמים במדויק** (למשל 113258 = ₪87,338).
- ✅ העלאת דוח ביצוע פר-דוח: `POST /api/reports/:id/budget-file` → בונה institutions + baskets + `budget_total`, מדליק דגל משתתפים.
- ✅ תקציב מול ניצול: `GET /api/reports/:id/budget`; מנוע הסטטוס מחשב `underUtilization = תקציב − ניצול` → מזין "כסף על השולחן" בלוח הראשי.
- ✅ ממשק: מסך דוח — כפתור "העלאת דוח ביצוע" + סקשן "תקציב מול ניצול" (תקציב/ניצול/תת-ניצול + טבלת מוסדות).
- ⚠️ פירוט פר-סל: כרגע נשמר התקציב הכולל פר-מוסד (מדויק). פיצול פר-סל (הדרכה/העשרה/גמיש/רכז/אבטחה) — לצעד 7 (התאמה תלת-כיוונית), שם הוא קריטי.
- ✅ **תוקן (2026-09-01) — באג "ילדים 0":** `num('')` החזיר 0 במקום null, ולכן תא ריק (תאים ממוזגים) בין תווית לערך בלע את המספר. עכשיו `numNear` סורק עד 3 תאים אחרי התווית.
- ✅ **תבנית גנים (2026-09-01):** גיליון "ריכוז נתונים" של הגנים ללא בלוקים פר-גן — המשרד מתקצב את גני הרשות כמקשה אחת. נוסף מסלול מצרפי (`parseAggregateSheet`): "מוסד" אחד = גני הרשות (סמל מוטב), עם ילדים לאחר בקרה, מספר גנים, רכזות, סלים, ותקציב = סה"כ נטו. **אומת מול קובץ אמיתי (נתניה): 815 ילדים, 29 גנים, תקציב ₪427,596 — תואם במדויק.**
- ✅ **הודעת "תקציב 0" (2026-09-01):** כשכל המוסדות בקובץ עם תקציב 0 (למשל: איוש משרות "לא תקין", ימי פעילות לא מולאו) — המערכת מסבירה מה חסר בקובץ המשרד במקום לייבא אפסים בשקט.
- ⚠️ נותר: תבנית מכינות קיץ טרם נבדקה מול קובץ מלא (יש רק תבנית ריקה).

## לשונית הכנסות משתתפים (2026-09-02)

- ✅ **מילוי אוטומטי בייצוא:** גבייה מדווחת = כמות ילדים (מדוח הביצוע/institutions) × תעריף לילד. התעריף מחולץ מקובץ המשרד בהעלאה ("תעריף לילד חלק ההורים", נשמר ב-`reports.parent_tariff`). גנים — שורה מרוכזת; בתי"ס — שורה פר מוסד (איתור השורה לפי הסמל הקיים בלשונית). נכתבים: סכום גבייה, כמות ילדים-גביה, מספר ושם כרטיס ההכנסות מהכרטסת. אומת: גנים 815×300=₪244,500; בתי"ס פר מוסד (למשל 170×300=₪51,000).
- ✅ **בדיקת התאמת הכנסות:** כרטסת ההכנסות מול הגבייה המדווחת (ילדים×תעריף); לקוח חייב מע"מ — הדיווח כולל מע"מ והכרטסת נטו (פער 18% צפוי, ההשוואה מנרמלת).
- ✅ עיגון זיהוי הלשונית על "שם כרטיס" (כותרת המקטע "דוח ביצוע כספי - הכנסות בפועל" הטעתה את העוגן הקודם).
- ✅ "פעילות" בשם כרטסת → סל העשרה; הערת המע"מ מוצגת רק ללקוחות חייבים; נתניה אינה חייבת מע"מ.
- ℹ️ לשונית "איוש משרות" מתמלאת לבד בנוסחאות המשרד — אין צורך במילוי. **כל לשוניות הקלט מכוסות: פירוט עלויות כח אדם · רכזות גנים · דוח הוצאות בפועל · תשלומי הורים.**
